## 4. 사용자 결정 항목

### 결정 1 — 닫기 목적지 (`§12.4-⑫`)

- 근거: Figma 전환 정의 없음(Prototype 확인 불가). 로컬 프로토타입 `HARU Home & Session.dc.html` 도 닫기에 `cursor:pointer` 뿐, 이동 핸들러 없음. 세션의 다른 종료는 전부 홈(`Discard` `D4-12` · ready 닫기). PRD §7.6 회고는 선택 사항이라 건너뛰기가 허용된다.
- **권고: 홈으로 `replace` 이동.** 서재는 근거가 없다. Stage 5 에서 카드가 붙어도 닫기 = 회고 건너뛰기로 의미가 유지된다.

### 결정 2 — 버블 보조 줄 `14 min together · sticker earned`

- 근거: Figma `88:929` 에 실재(최우선 규칙 3). 렌더 x100~292 · y403~414. 응답 필드 없음. `recordedSeconds` 로 조립하면 `architecture` §8 위반. `SessionBubbleCopySchema` = `{ text, templateId? }`.
- `min` 은 `D-6` 대상이 아니다: `D-6` 이 막은 것은 Home 헤더의 **집계** `12-day/115 Min` 이고 근거가 "비교·판정 금지"다. 세션 1회 길이는 사실 기술이다. 다만 판단은 사용자 몫.
- **권고: `SessionBubbleCopySchema` 에 `subtext` nullable 추가, 응답 값 그대로 표시, 값이 없으면 줄을 렌더하지 않는다** (`D4-22` 와 같은 처리). Mock 은 Figma 문자열. 대화 전용·스티커 미지급일 때의 문구는 서버 책임으로 `P4-BIP` 등록. 대안(미표시 + 허용 차이 등록)은 Figma 요소를 빼는 것이라 비권고.

### 결정 3 — `completionBubble` 재진입

- 근거: `sticker` 는 이미 `C4-OPEN-6` 으로 `SessionDetail` 에 재진입용 필드가 있다. 버블만 공백이다. `rules/qa.md` — Contract 가 요구를 못 담으면 PENDING 이 아니라 `FAIL`.
- **권고: `SessionDetail.completionBubble`(nullable) 추가.** 결정 2 와 같은 패스로 처리. Plan 의 "contract 변경 없음"과 어긋나므로 plan-agent 가 `API_CONTRACTS` 를 갱신한다. 서버는 전이 때 고른 템플릿 결과를 보존해야 한다 → BIP.
- 대안: 현행 수용 — 실제 재진입 경로가 새로고침뿐(§2.4)이지만 앱에서 새로고침·프로세스 복원은 일어난다. 그때 축하 문구 없는 화면이 된다.
- ⚠️ 어느 쪽이든 **오프라인 제출(`result: null`)은 해결되지 않는다** — 응답 자체가 없다. 스티커·버블 없는 화면이 Figma 누락 상태이며, 현행(메달리온만) 수용을 권고한다. 업로드 슬롯 `S4-H2` 와 함께 재확인.

### 결정 4 — Toast 겹침 (신규, VG-H1-02)

**① `useToastPresent` 공개 훅 — 승인 권고.** 도메인 지식이 없는 boolean 이라 Shared UI 경계(`packages/ui`)에 맞다 `[직독]`. 호출자는 `useStickerEntrance` 1곳이며, 별도 Context 라 값이 바뀔 때만 구독자가 리렌더된다. 대안은 더 나쁘다: `onDismiss` 는 퇴장 시작 시점이고 교체 시 안 불린다 · 앱 쪽 타이머는 duration 을 중복한다 · `.haru-toast` DOM 감시는 경계 위반이다. 위험: **`duration: 0` Toast 가 `held` 진입 중 뜨면 스티커가 무기한 숨겨진다** — 현재 앱 코드에 `duration: 0` 호출 0건(grep)이므로 지금은 도달 불가.
