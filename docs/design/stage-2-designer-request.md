## 1. 배경 — 이 화면 직전에 무슨 일이 있었나

보호자는 방금 온보딩 5단계를 마쳤다.

1. Step 1 아이 정보(이름·생년월·성별·관계·가정 언어·독서 루틴)
2. Step 2 기질
3. Step 3 좋아하는 책·집에 있는 책·관심 주제
4. Step 4 함께 키우고 싶은 것(성장 목표)
5. **Step 5 — Baseline Survey v1, 10문항** (`179:1770`)
   - 문항은 "지난 2주 동안 이런 모습을 얼마나 보았나요"를 묻는다.
   - 응답은 빈도 5단계(Never / Rarely / Sometimes / Often / Almost always) + **비채점 6번째 옵션**("Haven't had the chance to see this yet").
   - 6번째 옵션은 **낮은 점수가 아니라 "결측"** 이다. 설계 원문: *recorded as missing data, not as a low score*.

즉 이 화면은 **"당신의 아이는 이렇습니다"가 아니라 "우리가 함께 시작할 지점은 여기입니다"** 를 보여주는 화면이다. 바로 앞 화면(`179:1809`)의 문구도 **"Thank you — that's the starting point"** 다. 그 온도를 그대로 이어받아야 한다.

## 2. 화면 ① — 프로필 결과 (`C13-09`)

**Route**: `/onboarding/profile` · **가칭 frame 이름**: `1g · Profile result`

### 2.1 목적과 사용자가 그 순간 느껴야 할 것

| 목적 | 사용자가 느껴야 할 것 | 느끼면 안 되는 것 |
|---|---|---|
| 방금 답한 내용이 **아이에 대한 출발점**으로 정리되었음을 보여준다 | "우리 아이를 있는 그대로 봐 주는구나" · "여기서부터 같이 보면 되겠구나" · 안도감과 기대 | "평가받았다" · "점수가 낮다" · "다른 아이와 비교당했다" · "부족한 점을 지적당했다" |

핵심 감정 설계: **강점이 먼저 보이고, 성장 여지는 "다음에 함께 볼 것"으로 읽혀야 한다.**

### 2.2 반드시 있어야 하는 요소

| # | 요소 | 설명 |
|---|---|---|
| 1 | **아이 이름 인사** | first name만 사용 (예: "Here's where we're starting with Yuna"). **성(last name)은 절대 표시하지 않는다** |
| 2 | **다이아몬드 차트** | 4개 축(역량)의 1.0–5.0 값을 하나의 도형으로. 축 라벨 4개 필수 |
| 3 | **"판정이 아니다" 안내 문구** | 차트 근처에 1~2줄. PRD §7.3의 핵심 요구다. 작게 흘리지 말고 **읽히는 위치**에 |
| 4 | **강점 2개** | 값이 높은 역량 2개. "strengths" |
| 5 | **growing edge 2개** | 함께 키워갈 영역 2개. **"약점·부족"이 아니다.** 강점과 시각적 위계가 크게 차이 나지 않아야 한다 |
| 6 | **페르소나 카드** | 아이를 긍정형으로 묘사한 짧은 이름 + 설명 2~3문장 (서버 생성 문구) |
| 7 | **다음 단계 CTA** | 화면 ②로 이동 (예: "Next") |
| 8 | **점수 없음(`null`) 축의 표현** | §2.4 — **이 화면에서 가장 중요한 디자인 과제** |

넣지 않는 것: 다른 아이·평균과의 비교, 백분위, 등급/레벨, 이전 대비 변화(Stage 7 리포트 담당), 아이 사진, 성(last name), 생년월일 전체.

### 2.3 데이터 형태 (개발이 실제로 받는 값)

```
ProfileResult
├ child        { id, firstName }                       ← 이름은 first name 하나뿐
├ snapshot
│   └ scores[4]                                        ← 항상 정확히 4개, 순서는 디자인이 정한다
│       ├ capability : emotion_regulation | self_directed_agency
│       │              | cognitive_flexibility | intrinsic_motivation
│       ├ score      : 1.0 ~ 5.0 (소수 1자리) **또는 null**
│       ├ itemCount  : 채점에 쓰인 문항 수
│       └ missingCount : 비채점·미응답 문항 수
├ persona      { name, description, isFallback }       ← description 2~3문장
└ suggestedCapability : 위 4개 중 1개 **또는 null**
+ strengths[2] · growingEdges[2]                        ← 역량 키 배열 (null 역량은 후보에서 제외됨)
```

**역량 4종의 화면 표시 라벨 (확정 — 변경 불가)**

| 코드 키 | 화면 라벨 | 차트·배지 색 토큰 | 문항 수 |
|---|---|---|---|
| `emotion_regulation` | **Emotion Regulation** | `--color-capability-emotion-chart` (pink) | 2 |
| `self_directed_agency` | **Self-Direction** | `--color-capability-agency-chart` (green) | 3 |
| `cognitive_flexibility` | **Cognitive Flexibility** | `--color-capability-flexibility-chart` (cyan) | 2 |
| `intrinsic_motivation` | **Intrinsic Motivation** | `--color-capability-motivation-chart` (purple) | 3 |

> 색 = Figma `Tag 76:440` 의 green / pink / cyan / purple 과 **같은 색**이다 (결정 #19). 라벨 = 결정 #14.
> 문항 수가 2·3으로 다르다 = **축마다 표본 수가 다르다**. 필요하면 시각적으로 드러낼 수 있으나, "신뢰도가 낮다"는 인상을 주면 안 된다.

**페르소나 문구 길이 가정** — 이름 최대 24자, 설명 2~3문장(영문 기준 **약 110~220자**). 이 범위에서 카드 높이가 자연스럽게 늘어나야 한다. 말줄임(`…`)으로 자르지 않는다.

### 2.4 ★ 가장 중요한 과제 — 점수가 `null` 인 축

보호자가 어떤 역량의 문항 전부에 **"아직 볼 기회가 없었어요"** 로 답하면 그 역량은 `score: null` 이다.

| 반드시 지켜야 하는 것 | 하면 안 되는 것 |
|---|---|
| 축 **라벨은 그대로 표시**한다 (4축 도형 유지) | 축을 차트에서 **제거**하지 않는다 (도형이 깨져 비교 불가) |
| 값이 없음을 **"미관찰"** 로 표현한다 (예: 정점을 찍지 않고 점선·중립 처리) | **0 또는 1.0으로 찍지 않는다** (최저 판정으로 읽힌다) |
| 텍스트로도 "not observed yet" 톤을 전달한다 | 중앙값(3.0) 등 **대체값으로 채우지 않는다** |
| 강점·growing edge 후보에서 제외된다(개발이 처리) | 해당 축을 회색으로 "비활성"처럼 죽이지 않는다 — 누락이 아니라 **아직 보지 못한 것**이다 |

**필요한 변형 3가지**

| 변형 | 상황 | 디자인 필요 |
|---|---|---|
| A | 4축 모두 값 있음 | 기본 |
| B | **1~3개 축이 `null`** | 값 있는 축 + 미관찰 축이 **한 도형 안에 섞인** 상태 |
| C | **4축 모두 `null`** (전 문항 비채점) | 도형을 그릴 수 없는 상태. "아직 출발점을 그리기엔 이르다" 는 화면 — 차트 자리에 무엇을 둘지 결정 필요 |

> 변형 C에서도 온보딩은 **완료되고 Home으로 갈 수 있어야 한다.** 진행이 막히는 화면으로 만들지 말아 달라.

### 2.5 화면 상태 목록 (각각 디자인이 필요하다)

| 상태 | 언제 | 요청 |
|---|---|---|
| **Default** | 정상 | §2.2 전체 |
| **Persona loading** | 페르소나 생성이 최대 3초까지 걸릴 수 있다 | 차트·점수는 **먼저 보여주고** 페르소나 카드 자리만 대기 표시(스켈레톤). 전체 화면 스피너는 쓰지 않는다 |
| **Persona fallback** | 생성 실패 시 준비된 대체 문구가 온다 (`isFallback: true`) | **오류 화면이 아니다.** 시각적으로 실패처럼 보이면 안 된다. 구분이 필요하다면 아주 약하게 |
| **Score null (B·C)** | §2.4 | 필수 |
| **Error + Retry** | 프로필 조회 실패 | 기존 `ErrorState` 패턴 재사용 가능 — 새로 그릴 필요 없음 |
| **Offline** | 네트워크 없음 | 기존 Offline 배너 재사용 — 새로 그릴 필요 없음 |

### 2.6 접근성 요구 (필수)

- **차트 대체 텍스트**: 스크린리더가 읽을 문장 형식을 정해 달라. 값을 판정으로 읽지 않는 문장이어야 한다.
  예: *"Starting point for Yuna. Self-Direction 4.0 out of 5. Emotion Regulation 3.5 out of 5. Cognitive Flexibility not observed yet. Intrinsic Motivation 3.0 out of 5."*
- **색 단독 금지**: 축을 색으로만 구분하지 말고 **라벨 텍스트**를 항상 함께 둔다. 강점/growing edge도 색이 아니라 문구·아이콘으로 구분.
- **대비**: 텍스트 4.5:1, 비텍스트(차트 선·면·경계) 3:1 이상을 목표로 한다. 현재 팔레트가 미달일 수 있다 → §5 질문 Q2.
- **터치 타깃**: 눌러지는 요소는 최소 44×44pt.
- **모션**: 차트 그리기 애니메이션을 넣는다면 `prefers-reduced-motion` 에서 즉시 완성 상태로 표시되는 대체 동작도 함께 정의해 달라.

## 3. 화면 ② — 발전 역량 제시 (`C13-10`)

**Route**: `/onboarding/growth-capability` · **가칭 frame 이름**: `1h · Growth capability`

### 3.1 목적과 감정

| 목적 | 느껴야 할 것 |
|---|---|
| 앞으로 몇 주 동안 **함께 집중해 볼 역량 1개**를 고른다. 기본값은 서버가 제안하고, **보호자가 바꿀 수 있다** (PRD FR-06) | "정해진 게 아니라 내가 고르는구나" · "이 선택이 앞으로의 추천을 바꾸는구나" |

### 3.2 반드시 있어야 하는 요소

| # | 요소 | 설명 |
|---|---|---|
| 1 | 제안 문구 | 왜 이 역량이 기본값인지 한 줄 (판정 언어 금지) |
| 2 | **다이아몬드 차트 — 축 선택 가능 상태** | 화면 ①의 차트를 **인터랙티브**하게 쓴다. 축을 탭하면 선택이 바뀐다 |
| 3 | **현재 선택된 역량 강조** | 차트 안 + 차트 밖(라벨/배지/설명) **양쪽**에서 선택 상태가 보여야 한다 |
| 4 | 선택된 역량 설명 | 이 역량이 무엇을 뜻하는지 1~2문장 |
| 5 | 확정 CTA | 예: "Start with this" → Home으로 |
| 6 | 나중에 바꿀 수 있다는 안내 | 설정에서 변경 가능(Stage 6) — 부담을 낮춘다 |

### 3.3 상태

| 상태 | 요청 |
|---|---|
| **Default** | 서버 제안값이 미리 선택되어 있음 |
| **User changed** | 보호자가 다른 축을 선택함 — 제안값과 다르다는 것을 어떻게 보여줄지(또는 보여주지 않을지) 정해 달라 |
| **제안값 없음 (`suggestedCapability: null`)** | 모든 역량이 미관찰인 경우. **아무것도 선택되지 않은 상태**에서 시작하고, 보호자가 직접 고른다. 이때 CTA는 선택 전까지 진행 불가 — 그 이유를 어떻게 알릴지 포함해 달라 |
| **`null` 축 선택 가능 여부** | 점수가 없는 역량도 **고를 수 있어야 하는지** 결정이 필요하다 → §5 질문 Q4 |
| **저장 중 / 저장 실패** | CTA 버튼의 loading / 실패 시 인라인 안내 (기존 패턴 재사용 가능) |

### 3.4 인터랙션 요구

- **축 탭 = 선택**. 각 축의 터치 영역 **최소 44×44pt** (라벨 포함 영역으로 잡아도 된다).
- **키보드·스크린리더로도 선택 가능**해야 한다 → 축 목록을 라디오 그룹처럼 읽을 수 있는 **대체 UI(예: 차트 아래 선택 목록)** 를 함께 디자인해 주시면 가장 좋다. 차트만으로 선택하게 만들지 말아 달라.
- 선택 변화 모션은 짧게. `prefers-reduced-motion` 대체 동작 필요.

## 7. 문구 톤 — 반드시 지켜야 하는 규칙

| 쓰지 않는 표현 | 대신 쓰는 표현 |
|---|---|
| strong / weak, high / low, good / poor | "what we saw most", "where we'll look next" |
| score, rating, level, grade, assessment, diagnosis | "starting point", "what you noticed", "signals" |
| behind, needs improvement, lacking, below average | "not observed yet", "a place to grow together" |
| 다른 아이·평균과의 비교 | 아이 자신의 출발점만 |
| "failed", "invalid", "error" (사용자 문구) | "we couldn't ... right now" + 다음에 할 수 있는 것 |

- 느낌표·이모지를 쓰지 않는다.
- growing edge는 **"아직 보지 못한 것 / 함께 볼 것"** 이지 결핍이 아니다.
- 비채점 응답은 **결측**이지 낮은 점수가 아니다 — 문구에서도 그렇게 읽혀야 한다.

### 9.1 화면 — 알림 설정 (`C13-19`)

#### 9.1.1 왜 요청하는가

- 사용자 지시(2026-10-02): **"피그마를 기준으로 하여 알림 기능은 구현하지 않는다"** → 확인 질문 답변 **"설정 화면만 제외"**.

- Figma 에 현재 있는 것은 **`iOS 26/Toggle 17:113` 하나뿐**이고, 그것도 외부 iOS kit 이라 HARU 판 치수 근거가 되지 않는다 (§9.1.6 Q13).

#### 9.1.2 목적과 사용자가 그 순간 느껴야 할 것

| 목적 | 느껴야 할 것 | 느끼면 안 되는 것 |

#### 9.1.3 반드시 있어야 하는 요소

| # | 요소 | 설명 |
|---|---|---|
| 1 | **카드 갱신 시간** | 매일 Activity Card 가 도착하는 시각 1개 (기본 07:00). 값 1개 |
| 2 | **리마인더 on/off** | 켜면 아래 3·4 가 나타난다 |
| 3 | **리마인더 요일** | 7개 중 다중 선택 (일~토) |
| 4 | **리마인더 시간** | 값 1개 (예: 20:30) |

### 10.1 Activity Card 간격이 Figma 내부에서 어긋나 있습니다 (`A-3`)

MVP_KeyScreen_V.2 의 `163:2648` 에서 카드 3장의 x 좌표가 **245 / 616 / 991** 입니다 (카드 폭 365).
계산하면 카드 사이 간격이 **1→2 는 6, 2→3 은 10** 으로 서로 다릅니다.

가로 스크롤 트랙은 간격이 **균일**해야 하므로 둘 중 하나만 구현할 수 있습니다. 영향은 다음 카드가 **얼마나 보이는지**(peek)로 나타납니다.

| 간격 | 다음 카드 peek | 비고 |
|---|---|---|
| **6 (현재 구현)** | **8px** | 모서리 radius 28 곡선 밖이라 눈에 보입니다 |
| 10 | 4px | radius 28 곡선에 거의 먹혀서 "다음 카드가 있다"는 신호가 약해집니다 |

- **지금은 `6` 으로 구현해 두었습니다** (사용자 결정, approvals §13.5). peek 8px 이 "다음 카드가 있다"를 더 잘 보여주기 때문입니다.
- **요청**: Figma 의 세 카드 간격을 **하나로 통일**해 주세요. `6` 으로 통일해 주시면 구현과 일치하고, `10` 으로 가야 할 이유가 있으면 알려주시면 구현을 바꿉니다.
