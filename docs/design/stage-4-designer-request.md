## 1. 배경 — Stage 4 가 만드는 화면

보호자가 Home 또는 서재에서 "Start Session" 을 누르면 다음 순서로 진행된다.

```
세션 준비(ready) → 녹음 중(recording) ⇄ 일시정지(paused) → 완료(complete)
                                                   └→ (Stage 5) 회고 · 분석
```

Figma 가 가진 것은 **프레임 2개**뿐이다 (감사 §1.1).

| 노드 | 이름 | 크기 | 담고 있는 상태 |
|---|---|---|---|
| `28:51` | `1b · Session — Ready / Recording` | 393×852 | 이름은 "Ready / Recording" 인데 **`ready` 컨트롤과 `paused` 버튼이 한 화면에 있다** |
| `29:62` | `1c · Session — Complete & Feedback` | 393×852 | 상단 y 0~468 = 완료(Stage 4) · 하단 y 521~823 = 회고(Stage 5) |

그래서 **상태가 바뀔 때 화면이 어떻게 달라지는지**를 Figma 에서 읽을 수 없다. 그것이 요청 ①·② 다.

## 13. 이 요청서가 하지 않은 것

- **Figma 를 수정하지 않았다.** 모든 항목은 요청이며, 디자인 변경은 디자이너·사용자 승인 사항이다.
- **요청 범위(`C13-1` 잔여·`C13-14`)를 Design Spec 에 명세하지 않았다** (사용자 결정 8).
- **결정되지 않은 것을 결정으로 적지 않았다.** `78:353` 배치 · `S4F-18`(`Resume`) · `S4F-16`(바 규격) · `PF-04`~`08` · 타이포 2스텝 · §8 의 항목은 전부 **미결·질문**으로 표기했다.
- ⭐⭐ **해소된 항목을 조용히 지우지 않았다.** `C13-16`·`C13-17`·`Q0`·`Q1`·`Q4`(바)·`Q13'`·`Q14'`·§8-⑦·§8-⑧ 은 **머리말 이력 표**와 **취소선**으로 남겼다 — 디자이너가 1차 개정을 이미 보셨을 수 있어서다 (`R-BASELINE-1` 의 *"과도기 기록을 조용히 덮지 않는다"* 와 같은 원칙).
- ⭐⭐ **개발이 결정한 것과 요청하는 것을 섞지 않았다.** §8-② (pill 2줄)·②-b (pill 밀도)는 **개발 결정 + 확인 요청**이고, `Q2`·`Q3`·`Q4-b'`·`S4F-18` 은 **디자이너 판단이 필요한 질문**이다.
- 캐릭터 에셋의 **사용 권리를 다시 묻지 않았다** — `C-17` 로 확보돼 있고, 요청은 **표기·추적 기록**이다.
