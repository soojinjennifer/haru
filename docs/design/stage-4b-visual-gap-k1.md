## 6. Findings

|---|---|---|---|---|
| **VG-K1-01** | **safe-area 가 있으면 압축이 켜지지 않는다.** `viewport-fit=cover` + `AppColumn` padding 으로 콘텐츠는 줄지만 `@media (height)` 는 전체 viewport 를 본다. 시뮬레이션 852 + inset 59/34 → 콘텐츠 759 인데 `ring 190` · 팝업 331→624 · **Record(587) 를 37 덮는다** — K1 이전과 같은 결함. ready 는 바 bottom 830.6 으로 safe 영역(818)을 12.6 침범. 홈 화면 추가·Capacitor(`S4N-A`) 에서 재현 예상. Safari 탭 화면은 inset 0 이면 해당 없음 — iOS 툴바 상태별 inset 은 NOT VERIFIED | **Medium** (실기기 전) | 세션 높이 컨테이너 기준 `@container (height < …)` 로 교체 제안. 임계값·동작 불변, `K1-8` 의 `height` ↔ `dvh` 불일치 위험도 함께 사라진다 | **필요** |

## 8. development-agent 구현 메모 (승인 후)

- ⓐ 는 `session-prompts.css` 의 ③ 과 같은 구조지만 ready 는 2줄 pill 40 이다. 높이 예산에 아래 간격 14.4 를 넣는다 — 토큰 필요 시 design-agent 에 요청.

## 2차 3. `overscroll-behavior: contain` 제거 — 통과 (Chromium)

| 뷰포트 · 상태 | 제스처 1 | 제스처 2 |
|---|---|---|
| 320×568 ready · 팝업 | 목록 끝 (104 · 94), 뷰포트 0 | 뷰포트 60 |
| 375×548 ready · 팝업 | 목록 끝 (102 · 94), 뷰포트 0 | 뷰포트 80 |
| 393×460 ready · 팝업 | 목록 끝 (102 · 94), 뷰포트 0 | 뷰포트 168 |

- 대조: 320×568 ready 에 목록 `contain` 을 되돌리면 뷰포트 0 — 갇힘 재현. 제거가 원인을 푼 것이 맞다.
- 역방향도 목록 0 → 뷰포트 0 까지 돌아온다. 팝업은 제스처 중 열린 채다.

**628 이상 영향 없음**(393×700 · 393×628, ready · 팝업): 목록 끝까지 간 뒤 추가 제스처에도 뷰포트 0 · 루트 0, 목록 `contain` 복원본과 결과 동일.

- 대조: 뷰포트 `overscroll-contain` 을 끄면 같은 제스처가 루트를 503 움직였다. 즉 루트 전파 차단은 **뷰포트 쪽 `contain` 이 맡고 있고**, 내용이 넘치지 않는 스크롤 컨테이너에서도 Chromium 153 은 이를 적용한다.
- 부수 개선: 이전 `overflow-hidden` 뷰포트에는 `contain` 이 없었으므로, 목록 밖 제스처도 지금은 루트로 가지 않는다(393×700 측정 0, 끈 대조 303).
- ⚠️ 이 판단은 Chromium 근거다. 넘치지 않는 스크롤 컨테이너의 `overscroll-behavior` 처리는 브라우저별로 다를 수 있어 **Safari · Android 실기기는 `NOT VERIFIED`**. 628~795 목록 끝에서 페이지 고무줄 · 당김 새로고침이 생기는지 K2F-4 수동 확인에 추가한다.

## 2차 4. `FullscreenLayout` 공유 화면 부수 영향

`FullscreenLayout` 사용처는 `router.tsx` 의 라우트 그룹 한 곳이다. `topBar` · `footer` prop 을 넘기는 곳은 없다.

| 화면 | 확인 | 결과 |
|---|---|---|
| `/session/:id` 본 화면 | 2차 1~3 | 통과 |
| `/session/:id` 오류 (`--error`) | 앱 내 이동, 320×568 · 393×460 | 하한 미적용(높이 568 · 460) · 스크롤 0 · 가로 넘침 0 |
| `/session/:id` 대기 (`--pending`) | 코드만 — 오류와 같은 제외 규칙, 스피너 하나 | 측정 안 함 |
| `/session/:id/complete` | 393×460 · 끝에서 Submit | 현재 본체 `null` → 스크롤 0 · `scrollTop` 0 · Toast y 16~66. **S4-H1 후 위험** `VG-K1S-02` |
| `RouteErrorBoundary` fallback | 코드만 — 같은 뷰포트 | 넘치면 스크롤되므로 이전보다 안전. 측정 안 함 |

앱 코드의 뷰포트 스크롤 사용은 `useScrolledPast`(읽기, TopBar 전용)뿐이고 설정 · 리셋 코드는 없다. 이 레이아웃은 TopBar 가 없어 영향이 없다.
